# 学习状态协议

文件只保存接续教学所需的信息，讲解留在对话中。

## 存放与恢复

遵守项目 `AGENTS.md`。本项目具体课程放在对应周期的岗位目录，通常为 `<周期>/Builder式岗位准备/测试/<公司-岗位>/learning-state/`；通用 skill 留在 `skill/`。

先读已有记录再合并变化。用户当前明确指示优先，旧计划作为历史；明确重置后只使用用户保留的资料，不恢复已清除的课程记录。不同岗位分别保存状态。

## 三个文件

- **MISSION.md：目标与约束。**岗位与 JD、两项成功标准、用户指定的期限和投入、单次时长与教学偏好。教师暂定安排与用户约定分开，未知信息保留未知。节奏按 [自适应学习节奏](../SKILL.md#自适应学习节奏) 调整。
- **WORLD_MODEL.md：正在形成的工作模型。**先保存工作目的、日常任务、协作对象、负责人关注的结果与交付关系，再连接技术机制、候选工作与重要未知。链接 JD 和从业者资料，区分来源事实、教师假设与用户自己的理解，重要修订保留原因。
- **PROGRESS.md：接续位置。**记录用户当前怎样理解问题、哪里还不清楚、最近的表达或行动证据，以及下一步怎样接着讲。简记阶段安排和实际发生的节奏调整。已讲解与已掌握分开，用户自报与独立展示分开；实际用时未知就留空。

目标、理解或安排有实质变化时更新，已明确的约定不反复询问。教学位置不因资料读完而自动推进，文件创建和教师讲解也不作为用户能力证据。

## 来源与时效

来源直接链接在相关判断旁。战略判断按 [战略 grounding 的时效要求](../SKILL.md#战略-grounding-的时效要求) 保存截至日期、检索区间与官方入口、相关事件／发布日期，以及近期证据如何延续或修订判断。查阅日期单列；旧文重读不刷新年龄，证据不足标为待刷新。

源码阅读、实际运行与测量结果分别记录。贡献草案、实际参与和外部反馈分别记录。只保存有证据的信息，不为补齐文件猜测用户能力或公司内部情况。

记录较多、影响接续时再整理旧内容并保留链接；不按每轮对话创建讲义或日志。
