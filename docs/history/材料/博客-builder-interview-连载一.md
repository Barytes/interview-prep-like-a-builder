#  用 builder 心态准备面试skill

看了榛子在发光老师分享的找工作经验[《我面试的每家公司都给了我 offer｜成功率 100% 的秘诀（上）》](https://www.superlinear.academy/c/connections/offer-100)，对她利用chatgpt和curso搭建岗位的世界和工作语境，然后把真实工作做一遍的这个经历感到大为震撼。于是我想，我能学习这个能力吗？可能让大家都拥有这个能力吗？所以我尝试把这件事做成skill：https://github.com/Barytes/interview-prep-like-a-builder

## “怀着Builder心态准备面试”在做什么
就如榛子老师所说，“怀着 Builder 心态准备面试”是在尽可能重建这份工作的 context，“站在对方的组和视角里，想他们可能在做什么，每天面对的问题和语境是什么”。OpenAI的翁家翌在访谈中也强调了 [context 对工作的意义](https://www.bilibili.com/video/BV1darmBcE4A/)：一个人能够做好一项工作，很大程度上依赖于对项目背景的充分掌握。我前两天向鸭哥请教了一个问题，他给的[建议](https://www.superlinear.academy/c/q-a?message_id=2158863221#message_2158383162)也说明了同一个道理：借助 AI 加速实现的同时，人需要理解场景、用户和目标，提供关键背景，并参与方案选择与结果验收。带着这些认识去学习、做项目，再通过与从业者交流修正预判，面试准备就能逐步接近真实工作的思考和实践。
榛子老师是从跟chatgpt对话开始的。她先问清广告需求和库存分别指什么，再把问题缩到 Netflix 这类视频平台：预测依赖哪些信息，结果又会影响哪些决策。接着，她沿着供给、价格和广告主购买之间的关系自己做推演，把大型赛事、提前售卖广告位等情境放进去，追问原来的解释是否还成立。到了设计预测系统时，她又把各团队的需要带进来：他们要能解释业务变化，也要知道自己可以做什么。这份工作的 context，就是在这些具体的追问和修正里逐渐建立起来的。随后，她用 Cursor 按模拟数据分布和 granularity，再基于这些模拟数据建模、做 forecast。

## 尝试构建一个interview-prep-like-a-builder skill
我尝试构建了一个 `interview-prep-like-a-builder` skill，目标是帮助缺少相关工作经验的人，尽快了解一个具体岗位的context，能够从真正在这个岗位的人的视角出发去做工作（例如学习所需的知识、模拟真实的工作做一个项目等等）。
这个skill的底座是 Matt Pocock 的 [`teach` skill](https://github.com/mattpocock/skills/blob/main/docs/productivity/teach.md)。它会从“你加入了这个团队”讲起，介绍这份工作每天在做什么、关注的问题是什么、和谁合作，再按需要讲解相关知识，安排练习和情景问答。它会搜索这个岗位从业者的真实访谈、博客和工作分享，以及相关团队近期公开的产品更新、开源项目和技术进展作为教学材料。它会根据你的回答和理解调整讲解，帮助你逐渐形成自己的判断。
我设定了两条成功标准：
1. **能够解释目标团队的最新进展。** 
2. **能够跟上相关领域的前沿讨论，并做出一点贡献。**
我用 OpenAI 的 Applied AI Engineer（Codex Core Agent）岗位作为测试对象（当然没有准备进openai的意思，I wish I could🙏）。这个skill会搜索这个团队的成员（例如Tibo）的访谈，来说明这个岗位的工作日常，然后用 codex 仓库的最新 commit 作为教学示例。这是我用这个skill进行的[对话](https://chatgpt.com/s/cx_6ac7d3229d208191bad2f1f98254475c)，目前最新版本的skill只进行了几轮对话 ，大家可以看一下效果如何，也欢迎大家试用和改进。如果愿意分享试用感受，可以在文章下留言，也可以到仓库反馈。我个人目前对这个skill还是相当不满意，还要继续迭代。只能说是开始尝试如何获得和沉淀”搭建岗位的世界和工作语境，然后把真实工作做一遍“这个重要的能力，以及抛砖引玉，希望更有经验的朋友们也能来做这件事，真正变成能够帮助大家高效找工作。

## 问题
做这个skill有一个悖论：我自己也还在学习榛子老师的这套方法，却想先做出一个能教会这个方法的 skill。她在对话里能发现不合理的假设、追问缺失的条件，再把讨论拉回真实工作。这些能力依旧还是依靠人本身的能力和理解，目前很难写进 skill。
现在做这个skill还有四个问题：
1. **网上的材料能补出多少真实的 context？** 访谈、博客和开源项目能提供线索，但团队内真正的真实工作往往不会公开，依旧需要跟人聊才能得知。skill本身不能和从业者交流，怎样发现并补上这些空白？
2. **缺少经验的人，怎样判断 AI 讲得对不对？** 像我这样的 new grad，容易跟着ai的解释往下走，却很难像榛子老师一样不断地纠正ai的讲解，逼近真实工作。如果学习者本来就不知道真实工作是什么样，skill 要怎样帮助他逐渐形成判断，而不只是接受一套听起来合理的说法？
3. **怎样让教学始终围绕真实工作的世界模型展开？** 目前试用时，讨论很容易滑向具体技术，比如一路讲 harness 的运行原理。但是团队为什么要做这件事、这件事有没有价值之类的世界模型却很难有效地教学。这个skill做的事情是不是一个伪命题？缺少世界模型的人应该真正地去做这个工作，去找人聊天了解工作内容，而不是用skill跟ai对话。
4. **怎样检验这个 skill 确实有用？** 所有的测试都是依靠对话手动进行，并且不经过实践检验也不知道是不是真学到了。
